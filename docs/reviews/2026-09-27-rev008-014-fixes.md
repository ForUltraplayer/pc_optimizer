TRX는 `tests/PcOptimizer.Tests/TestResults/`에 있다. 기본 테스트 필터는 `Category!=Smoke&Category!=Online&Category!=ToolSmoke`, 실제 도구 포함 필터는 `Category=Smoke|Category=ToolSmoke`이다. 후자는 Windows 조회 권한을 가진 실행에서 검증했고 개인 캐시/설정을 정리하지 않았다. pip에는 기존 Codex 번들 Python을 `PCOPTIMIZER_TEST_PYTHON`으로 지정했으며 제품에는 해당 경로를 추가하지 않았다.

중간 실패도 구분한다. 첫 실제 8.3 테스트는 이 PC가 새 폴더에 짧은 별칭을 생성하지 않아 별칭 존재 단언에서 실패했다. 볼륨 설정은 바꾸지 않았다. 최종 실제 테스트는 별칭 지원 여부(`False`)를 기록하고 실제 경로 정규화/보호를 확인한다. 8.3 우회 자체는 결정적 가짜 경로 공급자 테스트로 검증했다. 남은 `~`를 거절하므로 합법적인 물결표 이름도 보수적으로 실행 불가가 될 수 있다.

중복 실행을 즉시 Busy로 거절하도록 보완한 뒤 병렬 npm/pip/NuGet fixture가 서로 충돌했다. 실제 도구 테스트를 같은 xUnit 컬렉션으로 직렬화한 뒤 23/23 통과했다. 그 과정에서 실행 중 테스트 DLL을 빌드하려 한 한 번의 파일 잠금 실패도 있었으며, 테스트 종료 후 재빌드에서 0경고/0오류를 확인했다. 최종 통과 TRX와 이전 실패 산출물을 혼동하지 말 것.

Kill 실패는 가짜 수명 제어 함수로 재현했다. 실제로 종료할 수 없는 프로세스를 생성하지 않았다. 핸들 기반 파일 경합 방지, 시스템 정책 변경, 다른 도구 정리로 범위를 넓히지 않았다.
