# PC Optimizer 1차 구현 계획

- 작성일: 2026-09-26
- 기준: [검토 수정 설계](../specs/2026-09-26-pc-optimizer-design.md)
- 구현·리뷰 시작 및 완료 보고 전 확인: [공유 리뷰 원장](../../reviews/REVIEW_LEDGER.md). 작업 전달 시 관련 리뷰 ID를 포함하고 대응·검증 근거를 원장에 기록한다.
- 상태: 구현 진행 중. 체크박스는 태스크 리뷰 통과 기준으로 갱신하며, 실제 PC 통합 검증과 배포 검증은 P7에서 한다.
- 산출물: Windows 11 x64용 C#/.NET 10 WPF 조회 전용 진단 앱
- 제외: 자동 정리/설정 변경/드라이버 설치, 실제 Elevated/Llm 프로젝트, 격리/삭제

## 1. 구현 원칙과 순서

프로젝트 4개와 의존 방향은 설계를 따른다. 검사 항목 하나가 수집→판정→화면까지 이어지는 최소 단위를 먼저 완성한 뒤 나머지를 확장한다. UI 완성과 엔진 완성을 별개 마지막 작업으로 미루지 않는다.

의존 순서:

`P0 환경/골격 → P1 계약/엔진 → P2 화면 수직 구현 → P3 하드웨어 → P4 파일 기반 → P5 규칙/앱 캐시 → P6 온라인 드라이버 → P7 통합 검증/배포`

외부 코드·규칙은 출처/라이선스 확인 후 가져오고 실제 제품의 파괴적 명령을 실행해 동작을 확인하지 않는다. 1차 작업에서 사용자 데이터 수정은 없으며 앱 로그·설정·fixture·리포트만 저장한다.

## 2. 예상 파일 구조

```text
PcOptimizer.sln
global.json
Directory.Build.props
src/
  PcOptimizer.Core/
    Models/                Finding, Measurement, ProbeResult, ScanContext, Report
    Abstractions/          IProbe, IRule, 예약 실행기/폴더 조언 인터페이스
    Engine/                규칙 평가, 오류 변환, 결과 병합
    Rules/                 분류별 순수 판정 규칙
    Cleaning/              INI 파서, 탐색 계획, 보호 정책 모델
  PcOptimizer.Probes/
    Hardware/              디스플레이, 메모리, 전원, 보안, 그래픽, OEM
    Storage/               볼륨/디스크/TRIM, 파일 순회, 중복/상위 폴더 집계
    Applications/          앱 설정 경로 리더, 시작 프로그램
    Drivers/               설치 드라이버, NVIDIA 어댑터, WUA 검색

  PcOptimizer.App/
    Services/              실행 조율, UAC 재검사, 허용된 링크, 로그/리포트
    ViewModels/            Main, FindingCard, 검사 상태
    Views/                 MainWindow, FindingCard
    Resources/             한국어 문자열, 스타일
tests/

    Unit/                  규칙/파서/엔진
    Integration/           임시 테스트 폴더·OS 어댑터 계약
    Smoke/                 실제 PC 검사(기본 제외)
    Fixtures/              비식별 WMI/JSON/INI/VDF/앱 설정 샘플

  winapp2.ini
  supplement.ini
  rule-metadata.json
  protect.json
  vendor-links.json
  sources.json
```

폴더 이름은 책임 분리를 나타낸다. 구현 중 필요가 확인된 파일만 생성하고 미구현 프로브를 성공한 것으로 반환하는 스텁은 배포하지 않는다. 보호·경로 정규화의 실제 OS 작업은 Probes에 두고 Core는 값과 순수 정책만 다룬다.

## P0. 개발 환경과 솔루션 골격

> 상태: 구현 완료·태스크 리뷰 통과 (2026-09-26, commit 4e54f87). 통합 검증은 P7
- [x] .NET 10 x64 SDK를 준비한다. 현재 `dotnet --info`에서는 SDK가 없으며, 런타임 설치만으로 빌드할 수 없다. 설치가 필요한 경로/권한은 실제 환경에 맞게 처리한다.
- [x] 설치된 SDK 패치 버전을 `global.json`에 고정하고 .NET 10 타깃의 4개 프로젝트와 참조 관계를 구성한다.
- [x] Nullable/분석기 설정, 공통 C# 헤더·상수·XML 주석 규칙, Windows 11/x64 지원 범위를 설정한다.
- [x] CommunityToolkit.Mvvm, WPF-UI, System.Management, xUnit, 테스트 SDK의 호환 버전을 검증·고정한다. 복원 lock 파일을 사용한다. 임의로 다른 UI 스택으로 전환하지 않는다.
- [x] 기본 `asInvoker` 매니페스트와 빈 WPF 창을 만들고 복원/Release 빌드/창 실행을 확인한다.

완료 조건: Core에는 Windows 패키지 참조가 없고, Tests는 Windows 타깃으로 Probes를 참조할 수 있다. WPF 창이 일반 권한으로 열리며 솔루션이 복원·빌드된다.

## P1. 수집·판정·실행 조율 계약

> 상태: 구현 완료·태스크 리뷰 통과 (2026-09-26, commits 813fe72·636601c·ecbe166·b8675e5). 외부 검증 결함 4건 반영. 통합 검증은 P7
- [x] Finding/Measurement/ProbeResult/Issue/Report를 구현한다. 상태 코드와 값 타입, UTC 시각, 관측 품질, 사용자 컨텍스트를 구분한다.
- [x] Candidate의 권고/근거 필수, CannotVerify의 사유 필수 등 모델 불변식을 검증한다.
- [x] IProbe는 ProbeResult만, IRule은 Finding만 반환하도록 한다. 예약 인터페이스는 타입 계약만 만들고 등록/호출하지 않는다.
- [x] 실행 조율 서비스에 검사 ID, 제한 병렬도, 권한/온라인 검사 정책, 타임아웃/취소, 늦은 결과 차단을 구현한다. 실제 스케줄러와 OS 작업은 Core 밖에 둔다.
- [x] 프로브별 성공/부분/실패를 화면용 결과로 변환하고, 한 프로브 실패가 다른 결과를 버리지 않도록 한다.
- [x] 실패·멈춤·늦게 반환하는 fake probe로 예외 격리/타임아웃/취소/중복 검사 억제를 확인한다.

완료 조건: 성공/실패/미실행/취소가 구분되며, 실패를 빈 결과나 Ok로 바꾸는 경로가 없다. 호출이 종료되지 않았는데 취소 완료라고 표시하지 않는다.

## P2. 최소 화면과 첫 실제 검사 연결

> 상태: 구현 완료·태스크 리뷰 통과 (2026-09-26, commit e6d67d4). WPF 실제 조작·배치 검증은 P7
- [x] MainWindow에 분류·카드·요약·시작/취소·검사 시각·온라인 확인 동작을 구현한다. MVVM 속성 변경은 UI 스레드로 전달한다.
- [x] 첫 실제 수집으로 메모리와 전원 상태를 연결한다. 메모리 속도 비교만으로 XMP 필요/적용을 단정하지 않는다.
- [x] 자세히 보기, 현재 검사에서 권고 접기, 허용된 설정 URI 열기, 비활성 Apply 설명을 구현한다.
- [x] 공용 로깅과 버전 있는 JSON 내보내기를 연결한다. 기본 내보내기에서 개인 경로·SID·장치 일련번호를 제거한다.
- [x] 현재 측정과 테스트 예시를 구분하고, 누락/실패 fixture로도 화면을 확인한다. 색상 외 판정 텍스트, 키보드 탐색, 긴 경로 줄바꿈을 검증한다.

완료 조건: 새 실제 메모리/전원 결과가 WPF 카드에 표시되고 취소/재검사가 동작한다. 리포트에 전체 개인 경로나 원시 예외가 기본으로 포함되지 않는다.

## P3. 하드웨어·보안·시작 항목 수집


> 상태: P3a(1~5번 항목) 구현 완료·리뷰 통과 (commits f3c657b·7de6324·a450fac). P3b(6~7번) 구현 완료·리뷰 통과 (commit a0ab605). 실제 UAC 취소 흐름은 P7에서 일반 권한으로 검증
- [x] 활성 디스플레이를 QueryDisplayConfig로 식별하고 EnumDisplaySettings 모드와 연결한다. 유리수 주사율과 정수 후보값의 정규화·59.94/60 차이 억제·동일 모드 조건을 테스트한다.
- [x] 모드 목록이 있어도 HDR/색심도/안정성 전체가 검증된 것으로 표현하지 않는다. 원격·복제·DRR 등 모호한 상태를 분리한다.
- [x] GPU/PnP 설치 정보, 제조사/모델/섀시·전원 연결 상태, HAGS/게임모드 설정값, DeviceGuard의 설정/실행 상태를 수집한다.
- [x] HAGS 키 부재, DeviceGuard 미지원, 배터리 상태 미상은 false로 대체하지 않는다. 메모리 무결성과 VBS를 같은 불리언으로 합치지 않는다.
- [x] 볼륨 여유, 디스크 제공자 상태, TRIM 삭제 알림 정책을 구현한다. Healthy를 SMART 전체 검사 완료로 표시하지 않는다.
- [x] Run/RunOnce·시작프로그램 폴더와 매칭 가능한 StartupApproved 상태를 읽는다. 실제 부팅 영향은 미지원으로 표시하고 정상/문제로 추정하지 않는다.
- [x] `runas` 진단 재시작, UAC 거절 시 기존 창 보존, SID 변경 시 시스템 범위 제한을 구현한다.

완료 조건: 일반 권한에서 가능한 실제 값과 불가능한 사유가 함께 표시된다. 디스플레이 모드가 특정 PC 숫자로 하드코딩되지 않고 다중 장치별 ID가 유지된다. 관리자 재검사가 원래 사용자와 다른 HKCU 결과를 혼합하지 않는다.

## P4. 공유 파일 스캔과 보호 정책

> 상태: 구현 완료·태스크 리뷰 통과 (2026-09-26, commits 9fed432·5399f00·4c901e4). REV-001/REV-002 수정됨·재검증 대기. 실제 대용량 폴더·일반 권한 창 검증은 P7
- [x] Known Folder·동기화 루트 등으로 protect 정책을 해석한다. 보호 정책 손상 시 파일 순회가 시작되지 않도록 한다.
- [x] 명시적 스캔 루트와 대상 사용자 프로필을 검증하고 정규화한다. 각 하위 항목에서 보호/제외/reparse/placeholder 조건을 재확인한다.
- [x] 파일 본문을 읽지 않는 메타데이터 순회, 볼륨당 제한, 취소/시간 예산, 접근 실패·변경 중 파일의 부분 집계를 구현한다.
- [x] 파일 ID를 이용한 하드링크/중첩 루트 중복 제거와 불가능할 때의 추정 표시를 구현한다. 논리 크기와 할당 크기를 구분한다.
- [x] 저장소/앱 캐시/미분류가 동일한 스캔 결과를 재사용하게 하고, 보호/누락 용량을 0바이트로 표시하지 않는다.
- [x] 완전 관측 미분류 폴더의 1,000,000,000바이트 경계, bottom-up 부모/자식 중복 제거, 동률 정렬, 상위 20개를 구현한다.
- [x] 임시 테스트 디렉터리의 중첩·링크·부분 실패를 검증한다. 대용량 임계값 시험은 fake metadata를 사용하고 실제 1GB 파일을 만들지 않는다. 테스트 정리는 검증된 테스트 루트 안에서만 한다.

완료 조건: 문서·사진·바탕화면·감지된 동기화 폴더 등 보호 루트의 내용이 스캔되지 않는다. 중첩 경로/하드링크로 합계가 부풀지 않으며, 부분 집계와 관측 용량이 UI에서 구분된다.

## P5. 규칙 파서와 앱 캐시 7종

> 상태: 구현 완료·태스크 리뷰 통과 (2026-09-26, commits fea0eae·99c1804·aff581b·18ea323). 규칙 4종+protect.json은 Probes 어셈블리 포함 리소스. 카드는 앱 단위(이 PC 108장). 비관리자 실행·실제 정션 E2E는 P7
- [x] Winapp2 원본의 커밋/해시/라이선스를 고정해 포함한다. 업데이트 자동 다운로드는 구현하지 않는다.
- [x] 지원 문법과 미지원 문법을 구분하는 INI 파서를 구현한다. 알 수 없는 제외/탐지 제약을 무시하지 않고 해당 규칙을 건너뛴다.
- [x] Registry 탐지와 파일 탐지는 Probes에 둔다. RegKey/삭제 플래그를 실행 기능으로 연결하지 않는다. 보호 정책 우선순위를 테스트한다.
- [x] 검토한 영향 설명·지원 앱 버전·참조를 rule-metadata에 기록한다. 커뮤니티 규칙에 이름만 보고 일괄 '삭제해도 안전' 문구를 붙이지 않는다.
- [x] Adobe/npm/pip/NuGet/Steam/NVIDIA 캐시/Squirrel 7종을 추가한다. 각 종류는 기본 위치 fixture와 지원 가능한 설정 재정의 fixture를 갖는다.
- [x] Adobe 설정 형식을 검증할 수 없는 버전은 기본 위치 범위와 확인 불가 이유를 표시한다. npm/pip/NuGet 설정의 비밀 값은 저장하지 않는다.
- [x] Steam 게임 본체가 캐시로 포함되지 않는지, Squirrel 버전 폴더가 미사용으로 판정되지 않는지, NuGet 외부 캐시 경로가 보호 정책을 우회하지 않는지 확인한다.

완료 조건: 7종 탐지와 스캔 범위/영향 설명이 구현되며, 지원/미지원 규칙 수가 보고된다. 앱 설정 위치를 모르면 기본 경로를 전체 사용자 설정이라고 주장하지 않는다.

## P6. 온라인 드라이버 비교와 공식 링크

- [ ] NVIDIA 조회를 HttpClient 어댑터 뒤에 격리하고 GPU/OS 매핑·필수 응답 필드·수치 버전·UTC 시각·HTTPS 허용 호스트를 검증한다.
- [ ] Game Ready/Studio 중복 버전·설치 버전 누락 시 Ambiguous로 표시한다. 사용자의 계열 선택은 '설치 계열 확인'으로 바꾸지 않는다.
- [ ] API 변경/오류/오프라인에서도 설치 드라이버 카드가 유지되도록 한다. HTTP 응답만 저장한 fixture로 기본 테스트를 실행한다.
- [ ] WUA 비동기 검색/취소를 구현한다. 숨김·설치된 항목 제외, 정책 차단·부분 결과 표시, 서비스/정책 불변을 확인한다. 다운로드/설치 API는 구현하지 않는다.
- [ ] AMD/Intel/OEM 공식 링크와 미지원 제조사 표시를 추가한다. 자동 다운로드나 자동 브라우저 열기는 하지 않는다.

완료 조건: 온라인 확인을 사용자가 시작하기 전에는 NVIDIA/WUA 네트워크 요청이 없다. 동일 계열 비교가 불가능하면 이유를 표시하며 오래된 버전 자체를 고장으로 표현하지 않는다.

## P7. 통합 검증과 1차 배포

- [ ] 12개 검사 분류를 설계 표와 대조해 성공/실패/권한/네트워크 처리 누락을 점검한다.
- [ ] 실제 PC에서 일반 권한·오프라인 검사, 취소/재검사, 사용자가 시작한 온라인 검사와 관리자 재검사를 검증한다. 다른 SID는 fixture/수동 재현 가능 범위를 기록한다.
- [ ] Windows 고급 디스플레이, 장치 관리자, 전원/보안 설정과 새 결과를 대조한다. 과거 120/130Hz·드라이버 버전을 합격 조건으로 고정하지 않는다.
- [ ] 100/150/200% DPI, 한글·긴 경로, 창 크기 변경, 많은 결과 카드, 키보드 조작, 확인 불가만 있는 화면을 확인한다.
- [ ] .NET이 없는 Windows 11 x64를 대상으로 self-contained 폴더 배포를 검증한다. 처음에는 단일 파일 패키징을 강제하지 않는다. 앱을 일반 권한으로 실행하고 UAC 재검사 경로가 배포에서도 동작하는지 확인한다.
- [ ] 배포 폴더에 규칙 원본/라이선스/버전 메타데이터가 포함되고 사용자 로그·실측 리포트·개인 경로는 포함되지 않았는지 검사한다.
- [ ] 빌드/테스트/수동 검증 결과와 미검증 환경을 기록한다. 자동 조치나 LLM 없이도 실제 상태를 읽고 설명할 수 있어야 1차 완료다.

## 3. 검증 명령과 실행 경계

실제 솔루션 생성 후 아래 명령을 사용한다. 현재 계획 작성 단계에서는 SDK가 없어 제품 빌드/테스트를 실행하지 않았다.

```powershell
dotnet --info
dotnet restore PcOptimizer.sln
dotnet build PcOptimizer.sln --configuration Release --no-restore
dotnet test PcOptimizer.sln --configuration Release --no-build --filter "Category!=Smoke"
dotnet publish src/PcOptimizer.App/PcOptimizer.App.csproj --configuration Release --runtime win-x64 --self-contained true --output artifacts/win-x64
```

실제 PC Smoke는 별도 명시적으로 실행하며 기본 테스트에서 OS 전체 스캔·네트워크 요청·UAC를 띄우지 않는다. 테스트 유형은 실제 구현에 맞춰 프로젝트 설정에서 고정한다. 단위 테스트가 통과해도 실제 PC 수집/화면/권한 검증을 대신하지 않는다.

## 4. 완료 판단

- 성공: 12개 분류의 조회 전용 흐름, 7종 supplement, 보호/부분 집계, 정확한 판정 사유, 일반 권한 시작, 명시적 온라인/관리자 재검사, 리포트와 배포 검증이 완료됐다.
- 명시적 제한: XMP 프로필 활성 직접 확인, 작업 관리자 부팅 영향, 드라이버 설치 호환성 최종 보증, 원격/복제/DRR 일부 모드, 지원하지 않는 앱 설정 형식은 확인 불가로 남긴다.
- 실패: 스캔되지 않은 위치를 정상/0바이트로 표시하거나, 알려진 숫자를 재현하도록 하드코딩하거나, 캐시 이름만으로 삭제 가능량을 약속하거나, 실제 제품 코드 없이 계획만으로 구현 완료라고 보고한다.

## 5. 후속 과제 메모 (2차 방향, 2026-09-26 검토 의견 반영)

- 현재 1차는 자체 진단 화면이다. 사용자가 기대한 "기존 도구 통합 사용"은 2차에서 진단 항목마다 연결할 Windows 기능·공식 도구·기존 프로그램(설정 URI, 저장소 센스, 벤더 드라이버 페이지, PC Manager/BleachBit 등)과 조치 후 재확인 항목을 표로 확정해야 완성된다. Winapp2 데이터 재사용만으로 통합 경험이 완성되지 않는다.
