## 범위와 작업 원칙

- 사용자 요청: NVIDIA ReBAR, 여러 GPU 옵션을 묶은 MPO fix 프로그램, NVIDIA/AMD 동영상 업스케일링, UEFI·안전 모드 재부팅의 조사와 후속 추가 구현. MPO 묶음은 `RedDot-3ND7355/MPO-GPU-FIX`를 조사 기준으로 삼되 모든 옵션의 일괄 채택으로 해석하지 않는다.
- 우선순위는 **기능 구현 → UI/UX → 검증**. 지원 계약을 확인하는 작은 기술 실험은 구현의 일부이며, 기능마다 ZIP을 만들지 않는다. 독립 리뷰·서브에이전트는 기존 사용자 지시대로 생략한다.
- 직접 조치를 목표로 한다. 외부 설정 연결만 추가한 항목은 직접 제어 완료로 집계하지 않는다. 하드웨어/드라이버가 지원하지 않으면 현재 PC에서의 제한과 남은 개발을 구분한다.
- 제품 방향 REV-004/015, 경로/로딩 REV-008, 실행 결과 REV-013, 사용자 범위 REV-016, 실제 작업 수명 REV-017/018을 유지한다. 원장의 기존 상태를 새 기능 검증으로 확대하지 않는다.
- 아래 신규 파일명은 예정 이름이다. 기존 공통 실행기·복원·링크 정책을 재사용하고 필요 시 계획에 실제 변경 파일을 기록한다.

## Task 목록

### T1 — 지원 여부·설정 상태·실행 대상 모델

- [ ] `src/PcOptimizer.Core/Advanced/`에 옵션 ID, 지원 여부, 관측 상태, 설정값/활성 상태, 재시작 필요, GPU/프로필 대상 모델 추가.
- [ ] `rules/advanced-options.json`은 표시 메타데이터와 닫힌 옵션 ID만 포함. 임의 레지스트리 경로·명령·DLL 이름을 실행 지시로 받지 않음.
- [x] 기본 3종의 `Core/Actions/ActionModels.cs` ActionId/ActionTarget 및 RollbackCodec을 호환성 있게 확장. 기존 저장 기록의 enum 의미를 바꾸지 않음. GPU 대상 모델은 후속.
- [ ] 원본의 존재 여부·타입·값과 앱이 적용한 값, 사용자 SID/세션, GPU/프로필 및 드라이버 계약을 복원 기록에 보존.
- 완료 조건: 미지원·조회 실패·기본값·꺼짐을 구분하며 확인되지 않은 옵션은 실행 대상을 만들지 않는다. 복원은 현재 값이 마지막 적용 값과 다르면 충돌로 안내한다.

### T2 — MPO·HAGS·게임 모드 직접 제어

- [x] NVIDIA 공식 MPO 첨부 REG 파일의 내용/해시/출처를 직접 확인하고 고정. 적용 DWORD 5·기본 복구 값 삭제, 세부 해시는 구현 보고서 참조.
- [ ] `Probes/Actions/Advanced/`에 닫힌 레지스트리 옵션 어댑터 구현. 기존 GraphicsSettingsProbe/Rule과 수집 중복 제거.
- [x] HKCU는 Full 사용자 범위에서만, HKLM은 등록된 시스템 조치로 실행. 실행 직전 다시 읽고 Pending 기록 후 변경·재조회.
- [x] MPO는 `사용 안 함 / Windows 기본 동작`, HAGS/게임 모드는 알려진 값을 표시. 기본값 복귀와 작업 전 원상 복원 구분. HAGS 값 부재·모르는 형식은 직접 변경 거절.
- 완료 조건: 삭제된 원본 값도 그대로 복원 가능. 저장된 값과 재부팅 후 효력 구분. RTX Video에 의한 MPO 변화는 레지스트리 강제 비활성과 따로 표현.

### T3 — UEFI·고급 시작 재부팅

- [ ] 고정 System32 shutdown.exe 실행 서비스 및 읽기 전용 UEFI/WinRE 가용성 확인 구현. 임의 BCD 수정·WinRE 활성화는 없음.
- [x] UEFI `/r /fw /t 0`, 고급 시작 `/r /o /t 0`의 고정 인자만 등록. `/f` 없음. 앱 안 5초 취소 대기 구현(`/t > 0`의 암묵 강제 종료 방지).
- [x] 공통 OperationCoordinator와 상호 배제. 실행 목적·미저장 작업·안전 모드 암호/필요 시 복구 키 안내 후 최종 확인. 암호/복구 키는 수집하지 않음.
- 완료 조건: 취소·전달 실패·전달 완료를 구분하고 “안전 모드 진입 완료”로 오표시하지 않는다. 이 Task는 **안전 모드 선택 화면 경유**만 완료한다.

### T4 — NVIDIA ReBAR 관측·프로필 계약

- [ ] `Probes/Advanced/Nvidia/`에 NVAPI/DRS 어댑터를 만들고 펌웨어 활성 상태와 게임별 드라이버 설정을 별도 수집.
- [ ] 공식 NVIDIA App 11.0.9의 게임별 기능, Profile Inspector 원본의 구/신 설정을 고정 버전으로 대조. `0x000BFA21`의 1은 Auto, 2는 On인 점 반영.
- [ ] 설치된 드라이버의 실제 설정 존재·형식·상속과 GPU 선택을 조회. 버전 문자열이나 BAR1 크기만으로 활성 확정 금지.
- 완료 조건: 공식 지원 API/문서와 커뮤니티 메타데이터 근거를 구분한 지원 표, 원본 읽기 fixture, 불명확한 조합의 거절 사유 확보. 전역 강제 켜기는 기본 대상에서 제외.

### T5 — NVIDIA 게임별 ReBAR 적용·복원

- [ ] T4에서 확인한 조합만 게임별 Auto/On/Off 대상으로 등록. 기존 원본 프로필과 명시 값 존재 여부 보관 후 고정 DRS 설정만 변경.
- [ ] 재조회·원상 복원·외부 변경 충돌·드라이버 교체 후 지원 재판정 구현. size limit/CPU exclusion 등 부가 설정을 묶어 변경하지 않음.
- 완료 조건: 읽기·쓰기·복원 기술 검증과 지원 장치 평가가 구분되어 기록됨. 프로필 On이 BIOS 비활성이나 게임 실행 중 실제 사용을 증명한다고 설명하지 않음.

### T6 — AMD Video Upscaling 공식 API

- [ ] `Probes/Advanced/Amd/`에 ADLX 초기화/지원 GPU 열거·IADLXVideoUpscale 읽기/쓰기/선명도 범위·정리 구현.

### T7 — NVIDIA RTX Video 직접 제어 기술 검증·구현

- [ ] 공식 SDK의 현행 지원 여부 및 비공개 video-settings 사용 프로젝트를 고정 버전으로 조사. 라이선스와 ABI·함수 로딩 경로 검토 후 최소 읽기 실험.

- [ ] 확인되지 않은 조합에는 공식 NVIDIA App 설정 위치 안내와 직접 제어 불가 사유 표시. 이를 직접 조치 구현 완료로 집계하지 않음.

### T8 — MPO 묶음 나머지 옵션과 안전 모드 직행의 추가 설계

- [ ] MPO-GPU-FIX의 ULPS, Shader Cache, OverlayMinFPS, Disable Overlays, Force Direct Flip, DX MOD, HDAUDBUS MSI 변경을 고정 소스로 확인하고 항목별 OS/GPU 조건·근거·원복 표 작성.
- [ ] TDR 일반 토글은 Microsoft 개발용 지침에 따라 제외 제안. RX 9000 ULPS 비활성화 경고 및 중복 오버레이 옵션은 개별 설명. 조사만으로 채택된 것으로 처리하지 않음.

### T9 — 고급 탭 통합 UI/UX

- 완료 조건: 어떤 개선을 기대하고 무엇이 실제 변경됐는지 한 카드에서 이해 가능. 기존 조치/복원 이력에 통합하고 고급 페이지가 별도 무관문 실행기를 갖지 않음.

### T10 — 별도 추가 후보 정리와 연결

- 완료 조건: 추가 추천 목록과 실제 채택/구현 목록을 분리. 지금 사용자 목록에 없던 모든 후보를 자동 승인된 기능으로 간주하지 않음.

### T11 — 회귀·통합·장치 평가

- [ ] 새 상태/복원 codec, 미지원·읽기 실패·값 부재·타입 불일치·외부 변경·SystemOnly·GPU 대상 변경·실행 중 종료/취소를 대역 또는 소유 fixture로 검증.

- [ ] UI 100/150/200%, 키보드, 좁은 창, 탭 복귀/내부 목록 스크롤, 긴 실패 사유 확인.

### T12 — 문서·통합 배포

- [ ] 원장/HANDOFF/기능 상태표를 실제 완료·부분 완료·평가 대기로 갱신. 서드파티 재사용 시 라이선스/고지·버전 고정 기록.

## 선후 관계와 중단 없는 진행

T1 → T2/T3 → T4/T5 → T6/T7 → T8 조사 → T9 → T11 → T12 순서로 묶어서 진행한다. T10은 별도 후보 표로 유지한다. 한 벤더 장치 부재나 비공개 API 조사로 막히면 해당 지원 한계를 기록하고 다른 구현을 계속한다. 다만 확인되지 않은 쓰기 API를 추측하여 활성화하지 않는다. Task 일부 완료를 전체 고급 기능 완료로 표시하지 않는다.
